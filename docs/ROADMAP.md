# 实施路线

[返回首页](../README.md) · [源码映射](SOURCE_MAP.md) · [验证方法](VALIDATION.md)

更新日期：2026-10-24。项目从同步执行开始，逐步学习 DeepInfer 的模型执行、结果提交和跨轮状态管理。每一阶段先交付可运行代码，再根据实际问题增加功能。

v0.1 已收敛到单设备文本推理与跨轮执行教学，能力矩阵、边界和发布检查见[v0.1 说明](RELEASE_v0.1.md)。第一次使用按[运行指南](START_HERE.md)，按机制阅读见[十四课索引](LEARNING_PATH.md)。下文记录阶段演进，后续章节不属于 v0.1 的完成条件。

## 第一阶段：单请求真实生成

当前代码已包含请求循环、逻辑槽位、Qwen2 forward、张量 KV Cache、离线生成与数值对照脚本。保留 DeepSeek-R1-Distill-Qwen-1.5B 回归基线，新增 Qwen3.5-0.8B / 2B 纯文本示例，限定单设备、eager、greedy 和短上下文。混合缓存与运行方法见[第四课](QWEN35.md)。

模型配置、tokenizer 与 safetensors 读取复用现有库；模型计算由本项目实现。入门模型采用 Qwen2 架构，用于验证执行和缓存，并不包含 MLA/MoE。

这一阶段的完成条件是：

- 在实际 Ascend 910C 环境运行真实权重，记录软件组合和输入。
- prefill 与固定 token 轨迹的 decode logits 对照参考模型，并报告误差。
- 缓存执行与完整重算对齐，请求结束后槽位可复用。
- 从干净环境按[第二课](REAL_GENERATION.md)运行，得到可复现的结果。

CPU 测试、小尺寸 NPU 测试和真实权重 NPU 测试分别记录。哪一项尚未完成，就保留对应说明。设备探测只覆盖当前实现需要的运算；stream、event 和图执行在实际使用时再验证。

## 第二阶段：同步多请求执行

同步动态批处理已加入：BatchEngine 按轮选择请求，Runner 合并输入做一次 forward，之后统一提交结果。支持新请求 prefill 与已有请求 decode 混合，带请求数与 token 预算。代码和运行方法见[第三课](BATCHING.md)。

现已支持可选的 chunked prefill：已有 decode 优先获得预算，prompt 分块写入缓存，最后一块才采样。继续检查不同长度请求持续加入、EOS、取消、容量不足和槽位复用。分页存储与融合 attention 留在已有实验表明需求后再加入。

当前采用短上下文的显式 attention mask，跨请求分数仍参与计算，不宣称性能改善。离线示例作为主要入口，HTTP 服务不影响本阶段验收。真实权重 CPU 与 Ascend 910C 验证分别记录，已随 v0.1 整理运行入口和证据索引。

## 第三阶段：DeepInfer 调度重叠实验

对照 `WorkerStepState`、`MetadataZOS` 和 `DeferredRelease`，研究当前轮 forward、上一轮结果处理、当前轮采样之间的依赖。

[第五课](STEP_STATE.md)已交付独立的零依赖 CPU 实验：手动控制完成事件，展示 `[A, B] → [B, C]` 的行号映射，以及取消后等 CPU 和设备全部用完才回收。它还没有接入真实模型或 NPU，不能算作调度重叠已经完成。

[第六课](NPU_EVENTS.md)进一步在实际 Ascend 910C 上通过微型张量的跨流、D2H 与回收检查；补上未记录事件的保护与缓冲区持有。该实验没有模型 forward，也不计作执行重叠或性能验收。

[第七课](DEFERRED_RUNNER.md)已让真实模型交回显式在途结果，读取后才提交主机进度。Qwen3.5-2B 在 Ascend 910C FP32 的六轮固定轨迹与同步 Runner logits 差异为 0，分块 prompt、取消后复用和 forward 提交后的主机异常清理通过。

[第八课](DEFERRED_ENGINE.md)把这份结果接到现有 BatchEngine，拆分 `launch_step()` / `finish_step()`，保留同步路径。真实 2B 六轮的十组 logits 对照差异为 0，覆盖动态加入、在途取消、槽位复用、长度/EOS 和主机异常清理；等待失败保留资源的控制流程通过 CPU 注入检查。仍只允许一批在途。

[第九课](PREPARE_DURING_STEP.md)加入逐条文本准备，将新请求分词放在结果收取之前。真实 2B 的批次和输出一致，但四条短请求未显示提速；另采的三步 trace 只有一步存在分词与设备 kernel 活动重叠。入口为显式选项，默认行为不变。

[第十课](SAMPLER_INPUTS.md)复用已有 trace 找到采样索引复制，将设备行号准备移到 forward 前。在同一份真实 2B 权重上，旧、新实现的 13 组完整 logits 最大差为 0；成对三步 trace 显示采样复制调用缩短、分词与设备尾部相交，而收取结果仍需等待。三组整轮计时含一次新版慢样本，尚不支持稳定提速。

[第十一课](DECODE_PIPELINE.md)在独立的固定批次实验中，将上一轮设备 token 直接送入下一轮，执行“本轮 forward → 上一轮结果处理 → 本轮采样”。真实 2B 四轮、八组 logits 与同步 greedy 差异为 0，换序、主机异常清理和 Runner 复用通过；没有动态成员、EOS 或性能结论。现有 BatchEngine 的单批限制保留。

[第十二课](STOPPING_PIPELINE.md)复用同一循环，实现 EOS、回调取消和成员退出。已经提交的后继轮次仍完成，输出丢弃，整请求缓存等最后使用事件后释放。真实 2B 三请求逐步缩批，九组完整 logits 最大差约2.10e-5，原容差通过；全部 EOS 的尾部、取消后的异常清理和复用也通过。仍无新请求加入或性能结论。

[第十三课](ARRIVALS.md)继续扩展同一循环，加入回调提交、FIFO 准入和混合 prefill/decode。C 等待 A 的最后使用结束后复用其槽位，与 B 的设备 token 合批；真实 2B 八组完整 logits 最大差约1.91e-5，冷缓存参考、尾轮到达、排队异常和复用均通过。没有新增 pipeline 类，仍是独立教学实验，没有性能结论。

[第十四课](CHUNK_PIPELINE.md)共用 Step 构造，以独立的已发出进度规划分块，以 CPU 已提交进度保存结果，以每请求最后使用事件控制回收。decode 优先、每轮输入预算、中间块不采样均接入原循环。真实 2B 九轮、十四组 logits 最大差约2.67e-5，四个中间块和取消异常清理通过，最终24/24槽位归还。

下一步先用不同 prompt 长度和到达时刻检查执行轨迹，明确预算下的等待，再决定调度职责的合并范围及需要计时的负载。主机准备和 eager 提交仍可能同步，性能收益另行验证。

完成条件包括状态与数值检查、请求进入/退出和取消时的资源安全，以及相同负载下的实际计时。延迟提交不是自动获得性能收益；没有明显提速的结果也如实报告。

## 后续章节

主引擎稳定后，使用 DeepSeek-V2-Lite / V2-Lite-Chat 学习 MLA 与 MoE。展开计算、压缩缓存和专家路由分别验证，并与对应模型的真实权重对齐。

投机解码先用可控 draft 解释验证、接受、提交与回退。模型 MTP/DSpark 需要相应权重和独立对照。SWA bounded replay 按适用模型与层级做独立实验，分别检查 mask/compact 一致性，以及近似回放相对完整重算的误差和任务质量。

融合算子、图执行、单机并行、跨机 PD、量化和完整 V4.1 部署，在已有实验表明其教学价值和需求后再展开。

## 交付约定

每项功能提供一个可运行示例、实现讲解、原版源码入口与简化说明。数值结果记录模型 revision、软件版本、dtype、输入和误差；性能结果另外记录设备、负载、统计区间和实验成本。

项目大小通过范围取舍控制，不预先承诺行数、性能比例或未经验证的硬件能力。
