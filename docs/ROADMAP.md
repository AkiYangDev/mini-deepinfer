## 项目要解决的问题

让读者在普通 CPU 上看懂一次请求怎样执行，再在 Ascend 910C 上用真实权重验证：输入怎样准备、前后轮怎样接续、结果什么时候提交、请求结束后缓存什么时候能再用。

DeepInfer 是执行与状态管理的主要设计参考。mini-sglang 提供紧凑实现和教学组织的参考；Ascend SGLang 帮助核查后端接口。Qwen3.5-2B 是当前真实运行的载体，换成 DeepSeek 模型本身并不能证明学到了 DeepInfer。

项目的价值在于：一个机制有小实现、有能观察的例子、有明确的原版出处，也有可以复核的结果。单设备、eager、greedy、短上下文仍是近期范围；CPU 入口和 Ascend 910C 验证一起维护。

## 已经完成的主线

- 同步单请求与动态批处理，分块 prefill、输入预算、EOS、取消和缓存回收。
- 输入准备、模型计算、采样和主机结果提交的拆分。
- 设备 token 跨轮接续，新请求与旧请求合批，最后使用事件保护缓存归属。
- Qwen3.5 纯文本计算、完整注意力 KV 与线性层状态，真实 2B 的 Ascend 910C FP32 对照。
- 自定义文本入口、A/B/C 完整演示、中英文运行指南和可安装的 v0.2.0。

实现的演进过程保留在[十四课](LEARNING_PATH.md)中。旧章节描述各自阶段的能力；总览文档应清楚说明当前最终状态。

## 第一轮：让 v0.2 容易理解和复现

先处理当前总览与历史叙述的混用。`ARCHITECTURE.md` 中“只有一批在途”等说明应限定到同步或 deferred 路径；跨轮路径的当前能力单独说清。`SOURCE_MAP.md` 的早期阶段说明也要带上上下文。尚未实现的模型和优化不能写得像已有模块。

对外保留一条短路径：

```text
CPU 的 A/B/C 演示 → 对着输出读执行循环 → Ascend 910C 真实文本 → 按问题选读章节
```

首页、仓库简介、版本说明围绕这条路径保持一致。安装包与 CI 已有的检查直接复用；只有命令、依赖或实际环境发生变化时，才增加对应验证。另一套 Ascend 环境需要单独的运行记录，不能由当前机器的结果推定兼容。

这一轮完成时，读者应能分清三件事：现在可以运行什么、哪些是历史教学步骤、哪些还在计划中。收集外部试用时，只要求必要信息：使用入口、版本、环境、失败位置或最难理解的一步。没有反馈时先保留入口，不猜测需求再增加功能。

## 第二轮：做一次有边界的性能对照

问题是：当前跨轮执行在什么短负载下改变延迟或吞吐，收益与额外开销各在哪里？现有分词位置实验不能替代这个比较。

| 项目 | 约定 |
| --- | --- |
| 模型与设备 | 现有 Qwen3.5-2B、单逻辑 Ascend 910C、FP32，固定模型 revision 与软件版本 |
| 对照方式 | 同步 BatchEngine 与现有跨轮循环，共用只读权重、独立缓存 |
| 负载 | 单请求、同长小批次、长短混合三类短负载；输入在计时前准备好，所有请求采用同一到达起点 |
| 对齐条件 | 输入 token、固定输出长度、EOS 设置、预算、并发、缓存容量、线程数和统计窗口 |
| 统计 | 离线 TTFT、TPOT、E2E、输出吞吐、失败数；记录 forward 次数、实际处理的输入 token 和请求结束后的额外计算 |
| 计时边界 | 明确从统一提交开始，到 CPU 可见输出及最终排空的各个终点；不包含分词、权重加载和缓存初始化，另列这些成本 |
| 实验规模 | CPU 先验证输出和统计；实机共用一次权重加载，每种路径预热，最多三组成对计时并交换先后顺序 |

固定成员的对照尽量保持相同批次计划。混合负载若因回收时机而产生不同计划，要保存这种差异，结论只针对整条执行路径，不能把全部变化都解释为 CPU/NPU 重叠。

计时关闭逐轮打印。不能按两种实现各自的完成轮次安排“同一批”动态到达；后续确有需要时，再用共同的到达时间表研究这个问题。

先检查端到端结果、执行次数和现有证据。只有结果留下一个具体、会影响优化决策的疑问时，才在计时之外采集少量 trace。慢样本保留；若三组结果波动大，就报告证据不足，不为了得到提速数字不断追加运行。

交付是一个可重复执行的对照入口、一份原始结果和一篇短报告。无论有没有提速，这一轮都可以完成。它不要求击败生产框架，也不把小负载结果推广到大规模服务。

## 第三轮：根据证据，只选一项改进

性能对照后再确定改动。每个候选先写清：耗时或复杂性在哪里、哪段代码造成了什么额外工作、最小修改是什么、如何判断值不值得保留。

| 观察到的问题 | 可以考虑的改动 | 保留条件 |
| --- | --- | --- |
| 重复准备元数据或不必要的同步 | 缩小一处准备/等待范围，继续明确持有对象与事件 | 相同输出与资源状态，配对计时或执行证据支持收益 |
| 教学计算本身占主要耗时 | 选择一个算子的参考/优化双实现 | 接口约束明确、数值通过，优化代码仍能独立阅读 |
| 多层接口使状态很难跟踪 | 删除真正重复的包装或整理状态归属 | 读者能沿同一路径理解，现有行为与异常清理保持 |
| 没有明确瓶颈或收益小于波动 | 保留现有执行实现，写清观察结果 | 不为性能数字增加长期维护成本 |

同步 Engine 仍作为容易理解的参考。同步、单批 deferred、跨轮执行的状态生命周期不同，不能仅为了减少类或行数把它们强行合并。新增能力复用现有循环；避免为每个教程再复制一个调度器。

证据检查方式已调整：旧版报告按索引中的固定 commit 校验，新版报告绑定新源码。CI 取得所需历史；`--current` 仍可显式检查旧报告是否与当前文件一致，相关源码变化时预期失败。保留原始报告，不能改旧 SHA 或放宽误差门槛来让新代码通过。

## v0.3：先完成最小投机解码教学闭环

[CPU 参考实验](SPECULATIVE.md)已实现可控候选、greedy 验证、接受/改正/bonus、输出提交和有效 KV 前缀回退。它与独立 greedy 输出及冷缓存 logits 对照，拒绝存储的 NaN 检查也通过；三步路线已收拢到 v0.3.0，运行顺序、检查范围和原始结果见[版本说明](RELEASE_v0.3.md)。

Qwen3.5 快照与重算也已完成 CPU 和 Ascend 910C FP32 检查，拒绝后的状态与冷缓存整段重算一致，复制字节与额外 forward 单独保存。[独立 lookup draft](LOOKUP_DRAFT.md)也已完成 CPU 和实机验证：候选只来自已提交历史，greedy 对照在事后运行。真实 2B 短输入接受 0/5，target 从10次变成12次 forward；它作为教学参考保留，没有性能收益结论。下面保留这条主线的设计依据。

完成前面的整理与对照后，若继续增加教学内容，优先评估 draft、verify、接受、提交与回退。这能沿着已经讲清的“已发出和已提交为什么不同”继续深入。

固定版本 DeepInfer 的验证、接受结果处理和后续长度修正已列入[源码对应](SPECULATIVE.md#这和-deepinfer-怎样对应)。当前使用可控 draft 与 greedy target，覆盖 CPU 小模型和 Ascend 910C 真实 Qwen3.5-2B，结果与普通 target greedy 一致，覆盖首次拒绝、中途拒绝、全部接受、EOS 和输出长度边界。可控 draft 是测试工具，不是 MTP/DSpark，也不能用它宣称真实加速。

Qwen3.5 的线性状态不能靠截断 KV 自动回退。同步参考现在复制卷积窗口与递推矩阵，拒绝后恢复并重算保留输入；真实 2B 每份快照约 19.27 MiB。该路径保持独立，不接入跨轮引擎，也不影响现有生成入口。下一阶段不同时扩展采样算法、跨轮投机和快照优化。

MLA/MoE、bounded replay、图执行、分页与共享前缀、分布式/PD、量化和 HTTP 服务都保留为候选。它们分别需要模型、数值或部署前提，不在同一版本同时推进。选入路线时必须说明它解决哪个具体学习问题，以及为什么现有例子讲不清。

## v0.4：双模型候选与实际成本

[双模型参考](MODEL_DRAFT.md)已完成：独立0.8B候选、2B验证，复用现有缓存和回退，加载前检查两套tokenizer文件与特殊ID。CPU覆盖不同权重、两种缓存和停止/异常边界；Ascend 910C真实权重检查宽度1和3，只对宽度1做三组成对计时。接受4/5、AL1.8，输出和状态正确，但whole中位数增加约31.2%。完整138forward、每模型一次已有权重加载，无下载或trace。

随后省去了只有一个候选时的 draft 快照：候选没有作为模型输入，缓存仍属于已提交前缀，无需回退。Ascend 910C 单独对照每请求少复制 101,007,360 字节，输出和模型工作量不变，三组成对 whole 中位数只下降约 0.7%。这一步保持独立同步参考，不成为默认加速路径。下一步优先处理复现反馈；继续分析性能时只选一个具体问题，不同时扩 MTP、概率采样、跨轮执行和更多模型。v0.3 正式 tag 和制品保留。v0.4.0 已收拢逐轮观察、自然拒绝的随机 CPU 例子、异常保护和失败报告；[发布说明](RELEASE_v0.4.md)列出完整范围。当前候选已重新通过 Ascend 910C 正常生成与状态验收，没有重测性能。下一轮先收集这条学习路径的复现反馈，不继续增加候选模式或通用异常框架。

## v0.5 开发：让现有机制接入实际生成

`generate --speculative` 已把用户文本接到已有的双模型同步参考，支持聊天模板、raw 输入、EOS、输出上限、逐轮观察和可选的独立 greedy 对照。Ascend 910C 上一个自定义聊天问题输出 `Paris` 后遇 EOS，两边各归还 35 个槽位。候选接受 0/3，没有计时或提速结论；完整命令与原始结果见[文本生成说明](SPECULATIVE_TEXT.md)。

同一条路径现已加入逐组流式输出和主动取消。取消在提交边界生效，完整接受组不会截断，停止后两份缓存同步并归还；可选 greedy 只检查已交付前缀，明确标记范围。CPU 覆盖早取消、EOS/长度优先、拒绝回退、消费者异常和拆字解码；一次 Ascend 910C 取消检查交付 4 个 token 后归还全部槽位，没有再启动一轮。没有另写验证循环。后续再逐项评估多请求投机、概率采样、图执行或 MTP 的模型与状态前提，不把这个单请求参考直接套进跨轮调度。

## 让项目被合适的读者看到

CPU 正温度的[投机采样参考](SAMPLING.md)已加入同一验证循环，包含小词表条件分布实验、普通采样的独立对照和两份缓存恢复检查。它尚未进行 Ascend 910C 验收；下一步只核对这条路径的数值与状态，不同时加入 top-k/top-p、MTP、图执行或多请求调度。

技术工作之外，准备一篇围绕 A/B/C 演示的项目介绍：从“请求结束后，缓存什么时候可以交给下一条请求”展开，放实际输出、运行命令、对应 DeepInfer 源码和当前边界。中文用于完整讲解，英文提供独立可读的简短介绍。

传播材料和代码使用同一个例子、同一个版本。比起频繁改首页口号，更需要读者能运行并提出具体问题。公开文章和社区交流按实际发布安排推进，本文不创建自动发布或消息任务。

贡献任务从真实缺口中挑选：一段难懂的英文解释、一个新的边界反例、一份另一套公开环境的复现记录。每个任务附复现入口、涉及文件和完成条件；没有具体缺口就不凑 Issue 数量。

版本回顾时优先看：是否有人独立跑通、哪里卡住、是否有人据此修改出一个例子、贡献是否容易审阅。Star 作为关注度的辅助指标，访问和克隆也不能直接换算成真实使用人数。

## 控制项目规模

每次只推进一项主要能力。新增内容至少回答一个已有读者问题或验证一个明确假设，并同时给出最小例子、原版出处和相应检查。代码按执行、模型、示例、验证区分职责，暂不为未来功能增加通用插件层或空目录。

“mini”靠选择范围和保留清楚的执行路径实现，不承诺一个掩盖测试与验证成本的行数。模型支持以现有 Qwen3.5 主例和 Qwen2 回归为基础，新增模型需有明确教学用途。

v0.2.x 用于复现和说明修正。下一次功能版本只围绕实际完成的一项能力命名；不预先承诺发布日期或性能倍数。验收与发布完成后结束该轮工作，再根据结果和反馈选择下一轮。
