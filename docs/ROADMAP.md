# 实施路线

[返回首页](../README.md)

更新日期：2026-10-20。已交付零依赖的同步执行骨架与 CPU 流程测试，见[第一课](FIRST_REQUEST.md)。M0—M5 的硬件、真实模型及进阶功能尚未完成；骨架演示不计作模型生成验收。

## 产品与教学目标

读者应能跟踪一个请求的完整生命周期，修改某一项缓存、调度或执行策略，并用正确性与性能数据解释变化。项目包含一个逐步成长的推理引擎，以及可以独立运行的 DeepInfer 机制实验。

核心实现以 Python 为主。模型 forward、调度、缓存与执行循环由项目实现；tokenizer、配置读取和权重文件读取可以复用成熟库。参考模型用于比较数值，正式引擎使用自己的执行路径。

部署报告、DeepInfer 和 Ascend SGLang 固定版本的具体参考作用，见[从设计参考到第一段实现](SOURCE_MAP.md)。

## 已交付：最小执行骨架

`Engine.step()` 串联 FIFO 准入、prefill/decode 元数据、Runner 调用和结果提交。逻辑槽位按请求预留，完成、取消和异常时回收。8 项标准库测试覆盖状态、资源重用、容量边界，以及小型缓存计算与完整重算的对照。当前没有真实模型或张量 KV。

下一步将 M0 的基础运算验证服务于 M1 的真实模型实现，先做单请求 eager 路径。

## M0：环境与适配验证

交付：可复现的软件环境清单、设备映射说明、基础算子验证脚本和原始结果。

- 记录实际芯片/逻辑设备枚举、可用 HBM、驱动、固件、CANN、Python、PyTorch 与 `torch_npu` 版本。
- 先验证 BF16 matmul、归一化、RoPE 所需基础运算、索引写入、gather/scatter 和 attention 参考计算。
- 单独探测后续可能使用的融合 attention 接口及形状约束，不把 import 成功视为可用。
- 检查 stream/event、设备计时及同步行为；图执行能力另列探测结果。
- 固定一个验证通过的环境组合，记录镜像 digest 或可复现的安装方法。

完成条件：短小的验证脚本能在目标 Ascend 910C 环境运行，每项能力有成功、失败或未验证的明确记录。单设备枚举与物理卡数量的关系有据可查。

## M1：单请求真实生成

交付：DeepSeek-R1-Distill-Qwen-1.5B 的独立模型实现、离线示例和第一篇代码教程。

- 读取模型配置和真实权重，实现 Qwen 架构所需的层。
- 使用 BF16、eager、greedy 和连续 KV 存储，先形成最容易追踪的执行路径。
- 实现 prefill、单步 decode、EOS 与输出长度上限。
- 对照参考模型检查单层输出、固定 token 轨迹的 logits，以及短文本生成。

完成条件：从干净环境按文档执行，能够得到真实模型输出；有数值误差记录和缓存一致性检查。仅展示“能聊天”不足以验收。

## M2：最小服务引擎

交付：请求生命周期、continuous batching、分页 KV 管理、chunked prefill 和基础流式 HTTP 服务。

- 分页存储先以可读的 gather/reference attention 路径证明正确，再优化 attention 计算。
- 对等待队列、运行队列和 token 预算做出明确的调度规则，覆盖不同长度请求持续加入的场景。
- 支持完成和取消；资源不足时采用明确的等待或拒绝行为，记录原因。
- 基础 Chat Completions 接口限定实际实现的字段，正确返回流结束标记、usage 和错误。
- 将模型计算时间与排队、调度、分词及网络开销区分开。

完成条件：混合长度请求能持续执行；请求之间无缓存串读；请求结束后块计数恢复。分页/chunked 与参考路径在固定轨迹下对齐。

**发布点：M2 通过后发布 v0.1 预览版。**

## M3：DeepSeek 架构主线

交付：DeepSeek-V2-Lite / V2-Lite-Chat、MLA 与 MoE 教程。

- 从清晰的 MLA 参考计算出发，解释展开后的 K/V 与压缩缓存的关系。
- 将压缩缓存作为独立实现步骤，验证它与参考计算的等价性和显存差异。
- 实现对应模型版本的专家路由、共享专家、token 分组和结果合并。
- 用小尺寸固定随机输入定位计算错误，再使用真实权重做整模型对齐。
- 分开记录权重、KV、临时工作区与框架预留内存；设备数和 batch/context 容量由实测决定。

完成条件：真实权重生成和数值检查通过；MLA 缓存与专家路由的教学示例可独立运行。基础 dense 模型通过不代表本阶段完成。

**发布点：M3 通过后发布 v0.2 教学版。**

## M4：执行优化与单机并行

交付：经实测选择的融合算子、图执行、调度重叠与单机多设备能力。

- 保留参考路径，将优化分项启用，按实际耗时决定推进顺序。
- 验证图输入缓冲区、batch 档位、padding 和缓存地址稳定性。
- 一轮流水重叠先画出事件依赖，再检查请求变动、取消和缓存延迟释放。
- 单机并行先明确模型分片、通信组和归约位置，再实现 HCCL 通信与数值验证。
- 避免为了抽象而同时引入多个尚无实现的设备后端。

完成条件：每项优化有功能回归、数值对照及统一负载下的实验；没有收益的结果同样保留。

## M5：DeepInfer 进阶机制实验

交付：独立可运行的机制实验及“原版—教学版”对应说明。

1. **调度重叠**：解释上一轮采样结果、当前批次重映射与设备执行之间的依赖。
2. **投机状态管理**：先用可控 draft 展示 verify、accept、commit 和 rollback。进一步接入模型 MTP/DSpark 需要兼容权重及独立对齐。
3. **SWA bounded replay**：先比较可见 key、位置与存储元数据，再在适用的模型/层级上比较输出。将 mask/compact 实现一致性与近似回放相对完整重算的误差/质量评估分开；SWA 本身不能自动证明整个模型可截断重放。

完成条件：假设明确，边界情况可测，每个实验有原版来源及适用模型说明。随机权重实验与完整 V4.1 服务验证分别记录。
